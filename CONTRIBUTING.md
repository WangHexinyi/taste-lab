# Contributing to SKILL.md

Thank you for your interest in contributing! This design system evolves through community feedback and real-world implementations.

## How to Contribute

### 1. Report Issues
- Use GitHub Issues for bugs or suggestions
- Include examples when reporting visual quality issues
- Specify if it's related to typography, color, motion, or imagery

### 2. Submit Examples
- Create new showcase implementations in `/examples`
- Follow the workflow checklist in SKILL.md Section 7
- Include a brief README comment explaining the design decisions

### 3. Improve Documentation
- Clarify ambiguous guidelines
- Add new anti-patterns discovered in practice
- Update escalation triggers based on successful cases

### 4. Accessibility & Performance
- Audit existing examples for WCAG compliance
- Optimize animation performance
- Test with screen readers and keyboard navigation

## Development Workflow

1. Fork the repository
2. Create a feature branch (`git checkout -b feat/your-improvement`)
3. Make your changes following SKILL.md guidelines
4. Test locally in multiple browsers
5. Submit a Pull Request with clear description

## Code Style

- Single-file HTML demos preferred for portability
- Tailwind CSS via CDN for styling
- Vanilla JavaScript (no framework dependencies unless necessary)
- Semantic HTML with accessibility attributes
- Mobile-first responsive design

## Review Process

All contributions are reviewed against:
- [ ] Adherence to SKILL.md Design Principles
- [ ] Visual quality meets "Default to Excellence" standard
- [ ] Accessibility basics covered
- [ ] Performance considerations addressed
- [ ] Code is clean and well-commented

---

**Questions?** Open an issue for discussion before starting large changes.
